# Intarsia Print — Spec

## What it is

A headless Python CLI. An image or text prompt goes in, a printable STL comes out. Use gemini via key to create a flat image for the next step: converts a flat, graphic image into a multi-layer bas-relief: the image's distinct color regions become discrete height levels, stacked in relief on a completely flat backing plate. Think intarsia, or a topographic map made from a poster.

Deterministic -- same input, same output. No ML, no GPU, no network calls.

## Context

Output feeds an Elegoo Saturn 4 Ultra (resin, 218 × 123 × 220 mm build volume, 19 µm XY resolution). Slicing happens downstream in Lychee Slicer. This tool's job ends at a clean, correctly scaled, manifold STL.

## Requirements

* Takes a text prompt or photo image, produces an STL
* Physical size is specified in millimeters and must be exact in the output
* Number of height levels is a parameter
* Level assignment works automatically on arbitrary images, with a mechanism to override it explicitly when the automatic choice picks badly
* Output is watertight, Z-up, flat bottom sitting on Z=0
* Output the image produced by Gemini, and have the user agree to it before running the STL creation
* App runs in claude code

## How to build it

Incrementally, committing as you go. Get each stage working and visually verified before starting the next.

The most important instruction in this document: after each stage, run it against a real image, open the output artifact, and look at it. Do not mark a stage done because the code reads correctly or the tests pass. Every failure mode in this project is silent and visual — a bad level separation runs without error, raises nothing, and yields a mushy unprintable model that looks fine as a file listing.

## Non-goals

Do not build these.

* Generative 3D mesh models
* Slicer integration or automation
* GUI or web interface, but do consider how the human will view the outputs along the way, perhaps just in the claude code desktop app.
* Extensive testing suite -- keep it minimal

## Domain knowledge worth having up front

These are properties of the problem, not instructions. How to handle them is your call.

* Input images must be flat and graphic. Gradients and patterns, especially small bits, and shading produce banded, noisy levels. Detecting unsuitable input and saying so beats silently producing garbage.
* Anti-aliased edges create spurious thin regions between levels and ultimately unprintable or messy artifacts — e.g. a one-pixel border that becomes real print geometry. JPEG compression artifacts do the same thing, worse. Again, think intarsia: large shapes noting regions of the photo and nothing else.
* The hard separations are hues that share similar brightness.
* Every pixel inside the subject must land in exactly one level. Unassigned pixels at region boundaries become pinholes in the mesh.
* Nested holes are real — an island inside a hole inside a shape — and naive contour handling gets them inside out.
* Features thinner than roughly 0.5 mm at final scale won't survive desupporting, regardless of what the printer can resolve.
* Per-level coverage percentage is a good bug signal. A level occupying 0.2% of the image is nearly always a separation error rather than a real feature.
* The initial image generated by gemini can solve (or unintentionally hinder) the final output, so a precise prompt at that point will save a lot later.
